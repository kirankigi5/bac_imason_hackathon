# Conversational AI Implementation Report

## Scope

This section records the earlier conversational-AI verification snapshot; the
subsequent FCC update is documented in `FCC_PIPELINE_REPORT.md`.

The then-existing official-data foundation was unchanged: 3,109 contiguous-U.S./DC
counties, 59,071 evidence rows, approximately 82.8% average configured-metric
completeness. This phase adds conversation and explainability only. The LLM never
selects the winning county or computes scores.

```text
User language -> validated intent -> canonical project -> deterministic engine
             -> real map/results -> verified facts -> LLM fact selection -> explanation
```

## Provider Interface

`LLMProvider` has asynchronous `parseProjectIntent(message, currentProject)` and
`generateExplanation(payload, audience)` methods. Both return a value and explicit
provider/mode status. `StructuredLLMProvider` accepts any implementation of
`StructuredTransport.complete(...)`; the first implemented remote transport is
OpenAI Responses. Other providers require a transport adapter, not changes to the
decision engine. Native server-side fetch avoids adding an SDK dependency.

Configuration: `LLM_PROVIDER=openai`, `LLM_MODEL`, and `LLM_API_KEY` or
`OPENAI_API_KEY`, supplied through the shell or `apps/web/.env.local`. Credentials
are never exposed as `NEXT_PUBLIC` variables or included in responses. Requests
use strict JSON Schema, disable provider response storage and have a 20-second
timeout. Configuration and mocked API handling are implemented; no live account
has been verified because credentials/model selection were not supplied.

## Supported Intent Schema

The strict external schema uses `capacity_mw`, `workload_type`, `geography`,
`target_go_live_year`, `planning_horizon_year`, `priority_changes`,
`constraints_to_add`, `constraints_to_remove`, `action`, `question`, `audience` and
`clarification`. Profile values are nullable when unspecified. Validated updates
map into the existing camelCase canonical state.

All seven priorities plus fiber are recognized. Relative increases/decreases
operate on current weights; fixed importance levels use backend targets. Every
redistributed weight is reported. Geographic restrictions support U.S. state
names/codes and configured regions. Numeric constraints are limited to wildfire,
drought, water-resilience score, grid-readiness proxy, fiber coverage and carbon
intensity. IDs and metric names are generated by the backend, not arbitrary model
strings. Explicit conflicts request clarification and do not modify the profile.
Planning horizon is stored only as context, not a scenario model.

## Follow-Up Logic

Backend readiness requires capacity, workload, geography, target go-live year, and
at least one explicit priority or hard constraint. It asks only the first missing
field in that order, preserving prior answers. A recommendation request does not
manufacture a priority. Direct search, comparison and explanation endpoints also
enforce intake requirements. Invalid JSON/schema inputs receive errors without
executing model-generated code.

## State Synchronization

`/api/project/converse` returns the accepted canonical profile, all changes,
deterministic results, optional computed deltas, explanation and provider status.
Chat and sliders consume the same response. Sliders bypass LLM parsing, and future
chat requests include their accepted values. Updates display old/new values and
profile/geography/weight/constraint type. Request IDs prevent stale responses from
overwriting later results. Excluded counties are not shown as map candidates.
Audience changes update communication style and refresh an already-requested
county explanation without altering the project or ranking.

## Explanation Payload And Grounding

Payloads contain the selected county, rank/score, project, category scores, effective
weights/contributions, observed passed/failed constraints, alternatives, evidence,
metric types (`measured`, `proxy`, `estimated`, `missing`), completeness and caveats.
Completeness is coverage, not a prediction-confidence probability.

The model selects/orders verified fact IDs. The server accepts only known IDs and
renders their catalog text, always appending mandatory caveats. Free-form model
claims are not rendered. This deliberately constrains prose to make grounding
enforceable. Missing FCC fiber, real site power capacity, negotiated tariffs, land
suitability, local approval, community acceptance and job creation cannot be
invented. Workforce context is not resident support or a job forecast.

Questions cover why here, why not second, biggest risks, trade-offs, what would
allow an alternative to outrank the selected county, and ranking changes. The
outranking answer uses current contribution gaps and the condition that recomputed
score and feasibility must improve; no sensitivity optimizer was added.

## Ranking Changes

The engine evaluates old/new complete profiles against the same feature snapshot
and all counties, not the visible top 20. Deltas record old/new ranks and scores,
each category's old/new effective weight and contribution, newly failing and
no-longer-failing constraint messages, and aggregate feasibility transitions.
Explanation payloads focus on prior/new leaders and the selected county. Without
a previous complete profile, the system explicitly declines to infer a cause.

## Fallback And Audience Modes

Missing provider configuration, HTTP errors, timeouts, refusals, malformed output,
invalid schema and unknown fact IDs use the deterministic fallback. Chat shows
fallback status. Developer, government and community modes use the same evidence
and mandatory caveats, with audience-specific emphasis and ordering. They do not
claim local support, opposition, approvals, guaranteed capacity or job creation.

## Remaining Blockers

Live LLM verification needs a configured server-side key and an account-supported
structured-output model. Only the OpenAI remote transport is currently implemented.
The subsequent FCC implementation uses the manually supplied official summary;
see `FCC_PIPELINE_REPORT.md` for the updated coverage and verification. The
original ZIP has not yet been supplied; CSV provenance is explicit. Real grid capacity, negotiated
tariffs, land suitability, documented local approval and community acceptance need
additional evidence. Community/news scraping, approval prediction, custom ML,
2050 scenarios, construction readiness, Pareto optimization and sophisticated
sensitivity analysis were intentionally not implemented. `CODEX.md` is not fully
complete overall.
